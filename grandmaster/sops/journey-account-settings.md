# Journey audit: Plan, account and every visible Settings page (Oct 3)

Read-only. Traced in code end to end: Settings › Plan (`settings/plan.tsx`), the plan store (`upshot-plan/index.ts`, `session.ts`), the account dialog (`upshot-plan/upgrade-dialog.tsx`), the Worker (`grandmaster/worker/src/auth.js`, `billing.js`, `model.js`, `index.js`), the chat model menu (`chat/components/input/model-menu.tsx`), the Settings shell (`settings/index.tsx`, `sidebar/settings.tsx`, `sidebar/settings-nav-groups.ts`) and every visible page: General, Profile, Plan, Insights, Appearance, Notifications, Transcription, Dictionary, Meetings, Calendar, Connectors, Imports, Privacy, Permissions, Developers. Granola refs: screens 12–19 (private) and docs.granola.ai/help-center/managing-your-account/subscriptions-and-billing.

Paths are under `apps/desktop/src` unless they start with `grandmaster/`. P1 = a judge hits it in the first 10 minutes or it breaks the journey; P2 = noticeable; P3 = polish.

## Checked and fine

- Yearly-first toggle, "$11 a month, billed $132 yearly / or $14 billed monthly", the total and renewal in Stripe's submit text, and "save 21%" (132/168) are correct and consistent with the Worker.
- The account dialog has visible labels, the password rule, Show password, Cancel, `autocomplete`, opens in the right mode, and switches to sign-in on `account_exists`; auth errors are plain words; email confirmation is off (night-log), so no dead confirmation link.
- Checkout → done page (logo, check, "Open Upshot" on `upshot://`, the scheme in the base tauri.conf.json used by release.sh) → window focus refetch → Pro; the BrowserStep flips to "You're on Upshot Pro".
- Cancel in the portal: `/billing/status` reads `cancel_at_period_end` live, so "Canceled. Pro stays on until {date}." shows on the next focus.
- Webhooks are signature-checked, order-safe, and an old ended subscription can't overwrite a newer active one.
- Pro model menu: free users get "Pro" chips and land on Settings › Plan; Pro picks persist and fall back to Auto when Pro ends; the Worker re-checks Pro server-side.
- Esc: the dialog, selects and the search box consume Esc before Settings closes (Radix `preventDefault`; `shouldSkipEscapeShortcut`).
- ⌘K "Plan" now updates the reused Settings tab (`reuseExistingTab` copies state), so the right row highlights.
- Previous fixes verified in code: Sign out moved to Profile, Free/Pro headers aligned, table in a card, "None yet" usage, sidebar name/email/badge, Translate icon, export description and ~/Downloads, switch off track `bg-input`, time zone "System (City)" with the full IANA list, Privacy telemetry rows gone, Appearance dead switches gone, Dictionary ungated, chips and webhook controls labeled, STT download/cancel/delete as menu items, Remove key confirm, last-of-Dock-or-menu-bar guard, disabled-row reason, Calendar "Allow access" as the one orange button with the list hidden until granted.
- Upstream checkout paths (`useBillingAccess().upgradeToPro`) are unreachable from visible pages: `isPro` is forced on and the cloud STT provider never counts as configured.
